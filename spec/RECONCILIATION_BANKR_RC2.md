# Reconciliation: Bankr "rc2" handoff vs AMP v0.3-draft

**Status:** informative. Nothing in this file is normative and nothing here changes SPEC text, schemas, reference code or vectors.
**Baseline:** `main` at `b0810fc`. Section numbers refer to `spec/SPEC.md` at that commit.
**Source of Bankr claims:** the rc2 handoff as relayed by the repo owner. The handoff itself is not in this repo; each claim below is quoted as relayed.
**Who decides:** the implementing agents (Bankr, zcode, Muse, others) and the owner, through the linked issues. This file only makes each divergence citable. Authority order per AGENTS.md: `/vectors` > SPEC > `/reference`.

Until an item is decided, the repo text is what conformance means: an implementation following rc2 on any item below will not reproduce `/vectors`.

| # | rc2 claim | Repo text (§) | Consequence if rc2 is implemented as-is | Options | Issue |
|---|---|---|---|---|---|
| 1 | Spec hash is plain `SHA-256(JCS(spec))`. | `canonical_spec_hash = H("AMP/spec/v1", JCS(spec))` (§5.4), where `H(tag, parts…) = SHA-256(ASCII(tag) ‖ 0x00 ‖ parts…)` and "no two uses share a tag" (§2.2). | Every `canonical_spec_hash` differs from the repo's, so every `market_id` differs; `vectors/market_id.json` fails. Untagged hashes lose the domain separation §2.2 relies on. | (a) rc2 adopts the tagged hash. (b) Propose dropping tags for this hash: breaking (AGENTS.md rule 3), needs a SPEC change, CHANGELOG entry and regenerated vectors. | #4 |
| 2 | Forecast is `forecast_bps` (uint16) inside the position call; commitment `keccak256(bps, salt, address)`. | Separate `FORECAST_COMMIT {commitment}` with `commitment = H("AMP/forecast/v1", market_id ‖ agent_id ‖ u32 p_ppm ‖ salt)`; `p_ppm ∈ [0, 1 000 000]`; "Forecasts are independent of staking" (§7.5, §2.4). SHA-256 is the AMP hash (§2.2). | `vectors/forecast.json` commitments fail. bps has 100× coarser resolution than ppm, so Brier values (§11) differ. Binding to a rail `address` instead of `agent_id` (§3.2) ties reputation to one rail. Coupling forecasts to positions means an agent must stake to forecast. | (a) rc2 adopts §7.5. (b) Coupling as an optional rail-level convenience that still emits a §7.5 commitment. (c) Change §7.5: breaking. See OPEN_QUESTIONS #13. | #5 |
| 3 | Forecasts are revealed before close. | `FORECAST_REVEAL {p_ppm, salt}` is "anchored after SETTLE, within reveal_window" (§7.5, §8 timing table). "Commit-reveal prevents forecasters from copying each other before close" (§11). | Forecasts become public while positions and commits are still open, so agents can copy them; the commit-reveal guarantee in §11 no longer holds. | (a) rc2 adopts reveal-after-SETTLE. (b) Change §7.5/§8: needs a replacement anti-copying argument. See OPEN_QUESTIONS #13. | #6 |
| 4 | RESOLVE carries an evidence root. | RESOLVE body is `{outcome, evidence[], bond}`, accepted iff `outcome == f(evidence).outcome` (§10.2); "The adapter executes `f` itself when a claim is anchored" (§10.1); adapters MUST "Execute `f` on RESOLVE and DISPUTE" (§13 item 4). PR #3 (OQ #2 design, §F.4) also assumes full `evidence[]`. | With only a root, the adapter cannot run `f`, so it cannot check RESOLVE, and it cannot check the DISPUTE rule "must change `f`" (§10.3). The deterministic game becomes an optimistic one. `vectors/arbitration.json` cases cannot be executed. | (a) rc2 adopts full `evidence[]` (PR #3 §G proposes caps of `2n` items × 640 B). (b) Root + on-demand evidence reveal on dispute: new mechanism, breaking. | #7 |
| 5 | Fees omit the treasury and add resolver gas stipends. | `creation_fee` → treasury (§5.3, §12); `fee_split_bps` is `{proposer, resolver, settler, treasury}` summing to exactly 10000 (§5.3); slashed bonds: 50% + dust to treasury (§10.5, §12). "There is no separate resolution or settlement fee" (§12). Stipends appear only as an open idea (OPEN_QUESTIONS #8). | `vectors/parimutuel.json` (`treasury_total`) and `vectors/arbitration.json` (`treasury_from_slash`) fail. Conservation (§9) must be re-proven for any stipend source. Treasury becomes optional per market. | (a) rc2 adopts §12. (b) Stipends from treasury per OPEN_QUESTIONS #8. (c) Make treasury optional: see OPEN_QUESTIONS #11. | #8 |
| 6 | Market schema has a metadata URI. | `schemas/market_spec.schema.json` and `schemas/market_instance.schema.json` both set `additionalProperties: false`; "No keys other than those listed are allowed, at any level" (§5.2). | Specs with the extra key are schema-invalid, and a conforming implementation rejects them. If added, it changes `canonical_spec_hash` (§5.4). | (a) Keep metadata off-spec (e.g. in CAPABILITY_AD or adapter storage keyed by `market_id`). (b) Add an optional field to the spec: breaking, needs SPEC + schema + vectors. | #9 |
| 7 | Resolvers and creators are banned from holding positions. | "Roles are not permissions. Any agent MAY perform any role" (§1.2). No position restriction exists anywhere in the spec. | rc2 would reject actions the spec allows, so two conformant implementations would disagree on validity. A ban keyed on `agent_id` is sybil-bypassable because `agent_id = H("AMP/agent_id/v1", alg ‖ root_pubkey)` (§3.2) is free to create. | (a) No rule (spec as-is). (b) Public on-page flag. (c) Hard ban: new normative rule. See OPEN_QUESTIONS #12. | #10 |
| 8 | Single home rail plus mirrors is decided. | "The same canonical spec MAY be instantiated on several rails. Each instance has its own `market_id`, pools and resolution game" (§1.1). Home rail + mirror is listed only as an option under OPEN_QUESTIONS #6 (DEFER-OK, open). | Treats an open question as closed. Mirroring a result across rails is a new mechanism with its own trust assumptions (a bridge), which the spec does not define. | (a) Keep OQ #6 open; rc2 runs one rail without mirrors. (b) Decide OQ #6 explicitly through its own design review. | #11 |
| 9 | Class B zkTLS is drafted. | "The verification profile for attested HTTP is **not yet specified**… In v0.3, Class B sources are restricted to signed observations" (§6.1). OPEN_QUESTIONS #1 is open and BLOCKS-FREEZE for Class B. PR #3 §H proposes a `profile` registry as the hook. | A zkTLS draft outside the repo is not reviewable and not part of v0.3. Markets using it would not be resolvable by other implementations. | (a) Submit the draft as an OQ #1 design PR. (b) Keep Class B = signed observations for Season 0. | #12 |
| 10 | Freeze signers include Grok. | `ACKS.md`: "_none yet: v0.3 is a draft_"; each implementer signs the freeze hash "with its AMP root key". The freeze hash is undefined (OPEN_QUESTIONS #10, BLOCKS-FREEZE). | No one can sign a freeze yet. Grok has no published AMP root key or implementation in this repo, so listing it as a signer has no basis. | (a) Close OQ #10 first, then implementers sign. (b) Grok is listed only after it publishes a root key and passes `/vectors`. | #13 |
